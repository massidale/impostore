# Just One — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** rilasciare Just One come plugin completo e autonomo.

**Architecture:** `justOneModule` implementa GameModule della fase 0; client con tre componenti GamePlugin e wrapper roomCommand. Segreti e punti esclusivamente server.

**Tech Stack:** TypeScript, React Native/Expo, Firebase callable + RTDB, node:test ed emulatori esistenti.

**Spec:** [progetto funzionale](../specs/2026-09-06-new-games-design.md), sezione Just One; [base e criteri comuni](2026-09-06-new-games.md).

## Vincoli globali

Firebase UID e autorizzazione per fase/ruolo; partecipanti congelati, spettatori dalla partita successiva; nessun segreto alla vista host; carte adattive e controlli almeno 44×44; niente AI per arbitrare; italiano; Lupus resta disabilitato. Le regole e i limiti numerici della sezione corrispondente della spec sono vincolanti per questo piano.

## File e interfacce

- Creare `server/games/just-one.ts`: modulo `justOneModule`, validazione e transizioni server.
- Creare `server/data/just-one.json`: contenuti originali validati; dati riservati fuori dal bundle UI.
- Creare `src/games/just-one/types.ts`, `index.ts`, `services/justOneLogic.ts`.
- Creare `src/games/just-one/components/SettingsPanel.tsx`, `HostDashboard.tsx`, `PlayerGamepad.tsx`.
- Creare `tests/server/just-one.test.ts`, `tests/integration/just-one.test.mjs`.
- Modificare `server/gameModules.ts`; al rilascio modificare `src/core/gameRegistry.ts`, `DOCUMENTAZIONE.md` e includere il nuovo file di integrazione nello script `test:integration`.

**Consuma:** `GameModule`, `getGameModule`, `RoundExpected`, `roomCommand(roomId, method, [payload])`, `FitContent`, `useGameAction`, `HostDashboardShell`, `loadServer` dalla fase 0.

**Produce:** `justOneModule: GameModule`, plugin con ID `just-one`, impostazioni `{ rounds: number }` e funzioni pure `survivingClues(clues: Record<string, string>): string[]; normalizeClue(value: string): string`. I helper sono esportati dal modulo server per il collaudo; la UI non li usa per attribuire punteggi.

**Comandi specifici**, prefisso `just-one.`: submitClue({text: string}), withdrawClue({}), flagClue({authorUid: string}), confirmReview({}), submitGuess({text: string}), pass({}), nextRound({}). Il payload non contiene l’UID dell’autore; l’attore viene da Auth. Restano disponibili le azioni comuni validate nella fase 0.

**Stato:** `clues → review → guessing → roundResults → clues/results`.

**Riservato:** target, aliases, rawCluesByUid, mazzo futuro.

**Vista client:** guesserUid, stato degli invii; autori/indizi nella review solo ai suggeritori; validClues anonimi all’indovino in guessing; target a tutti dopo il risultato.

## Task 1 — motore e proiezioni

- [ ] Scrivere in `tests/server/just-one.test.ts` il test iniziale:

```ts
import test from 'node:test';
import assert from 'node:assert/strict';
import {loadServer} from '../helpers/serverLoader.ts';
test('just-one: regola fondamentale', () => {
  const {survivingClues} = loadServer('server/games/just-one.ts');
  assert.deepEqual(survivingClues({a:'Caffè', b:'CAFFE', c:'bar'}), ['bar']);
  assert.deepEqual(survivingClues({a:'mare', b:'mare', c:'mare'}), []);
  assert.equal(survivingClues({a:'mare', b:'marino'}).length, 2);
});
```

- [ ] Eseguire `node --experimental-strip-types --no-warnings --test tests/server/just-one.test.ts`; verificare un fallimento dovuto alla funzionalità assente.
- [ ] Implementare helper e modulo `justOneModule`: Raccogliere una parola per suggeritore. Annullare tutti i duplicati normalizzati, rifiutare indizio uguale all’obiettivo e applicare review/ritiro secondo la spec. Mascherare autori all’indovino e mescolare gli indizi rimasti. Un tentativo o passaggio per round; +1 cooperativo solo se obiettivo/alias combacia. Zero indizi validi chiude il round con zero punti.
- [ ] Validare settings e contenuti sul server prima di start; predisporre il dataset: 100 parole originali con alias espliciti. Creare anche server/textNormalization.ts per le funzioni condivise; non importare mazzi server nel bundle UI.
- [ ] Aggiungere test delle seguenti transizioni e proiezioni, poi eseguire nuovamente il test specifico:
  - Target, alias, rawCluesByUid e autori non arrivano all’indovino; nemmeno se è host.
  - Indizi identici dopo normalizzazione vengono cancellati tutti, inclusi gruppi di tre; nessuno rimane come rappresentante.
  - Due autori distinti confermano una segnalazione; un solo autore non può cancellare arbitrariamente un indizio altrui.
  - Ultimo invio e ultima conferma review avanzano una sola volta; tentativo/passaggio consumano una sola parola.
- [ ] Confermare stato input non mutato dall’engine, punteggi aggiornati una sola volta e token obsoleti rifiutati. Registrare il modulo nel registro server; revisione e commit mirato del backend, senza catalogo client.
