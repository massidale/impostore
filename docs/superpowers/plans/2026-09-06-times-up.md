# Time’s Up — tre round — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** rilasciare Time’s Up — tre round come plugin completo e autonomo.

**Architecture:** `timesUpModule` implementa GameModule della fase 0; client con tre componenti GamePlugin e wrapper roomCommand. Segreti e punti esclusivamente server.

**Tech Stack:** TypeScript, React Native/Expo, Firebase callable + RTDB, node:test ed emulatori esistenti.

**Spec:** [progetto funzionale](../specs/2026-09-06-new-games-design.md), sezione Time’s Up; [base e criteri comuni](2026-09-06-new-games.md).

## Vincoli globali

Firebase UID e autorizzazione per fase/ruolo; partecipanti congelati, spettatori dalla partita successiva; nessun segreto alla vista host; carte adattive e controlli almeno 44×44; niente AI per arbitrare; italiano; Lupus resta disabilitato. Le regole e i limiti numerici della sezione corrispondente della spec sono vincolanti per questo piano.

## File e interfacce

- Creare `server/games/times-up.ts`: modulo `timesUpModule`, validazione e transizioni server.
- Creare `server/data/times-up.json`: contenuti originali validati; dati riservati fuori dal bundle UI.
- Creare `src/games/times-up/types.ts`, `index.ts`, `services/timesUpLogic.ts`.
- Creare `src/games/times-up/components/SettingsPanel.tsx`, `HostDashboard.tsx`, `PlayerGamepad.tsx`.
- Creare `tests/server/times-up.test.ts`, `tests/integration/times-up.test.mjs`.
- Modificare `server/gameModules.ts`; al rilascio modificare `src/core/gameRegistry.ts`, `DOCUMENTAZIONE.md` e includere il nuovo file di integrazione nello script `test:integration`.

**Consuma:** `GameModule`, `getGameModule`, `RoundExpected`, `roomCommand(roomId, method, [payload])`, `FitContent`, `useGameAction`, `HostDashboardShell`, `loadServer` dalla fase 0.

**Produce:** `timesUpModule: GameModule`, plugin con ID `times-up`, impostazioni `{ turnSeconds: number; deckSize: number; teamMode: "auto" | "manual"; manualTeams: Record<string, "blue" | "red"> | null; contentSource: "default" | "custom" | "players" }` e funzioni pure `resetRoundDeck(originalIds: string[], shuffle: (ids: string[]) => string[]): string[]`. I helper sono esportati dal modulo server per il collaudo; la UI non li usa per attribuire punteggi.

**Comandi specifici**, prefisso `times-up.`: submitNames({names: string[]}), beginTurn({}), resolveCard({outcome: "correct" | "skip" | "violation", actionVersion: number}), undoCard({actionVersion: number}), endTurn({}), nextRound({}). Il payload non contiene l’UID dell’autore; l’attore viene da Auth. Restano disponibili le azioni comuni validate nella fase 0.

**Stato:** `collecting opzionale → ready → turn → turnResults/roundResults → ready/results`.

**Riservato:** originalDeck immutabile, pendingCardIds, cursor e mazzo futuro; currentCard soltanto al descrittore.

**Vista client:** roundNumber 1–3, regola attiva, squadre, descrittore, tempo residuo server, numero carte rimaste e punteggi; mai l’intero mazzo prima dei risultati.

## Task 1 — motore e proiezioni

- [ ] Scrivere in `tests/server/times-up.test.ts` il test iniziale:

```ts
import test from 'node:test';
import assert from 'node:assert/strict';
import {loadServer} from '../helpers/serverLoader.ts';
test('times-up: regola fondamentale', () => {
  const {resetRoundDeck} = loadServer('server/games/times-up.ts');
  const original = ['a', 'b', 'c'];
  const round2 = resetRoundDeck(original, ids => ids.reverse());
  assert.deepEqual([...round2].sort(), [...original].sort());
  assert.deepEqual(original, ['a', 'b', 'c']);
  const round3 = resetRoundDeck(original, ids => ids);
  assert.deepEqual(round3, ['a', 'b', 'c']);
});
```
